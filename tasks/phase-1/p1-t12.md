# infra(saascript-frontend-web): Containerize SaaScript Web Frontend Application

**1. Rationale:**
Containerizing the main web frontend application (`frontend/web/`) is a crucial step towards achieving a portable, consistent, and scalable development and deployment environment. By creating a Dockerfile and integrating the frontend into the `infra/docker-compose.yml` setup, we ensure that the application can be run reproducibly across different developer machines and aligns with our overall architectural principles. This also simplifies the local development workflow by allowing the frontend to run alongside backend services, streamlining testing and integration, as outlined in `architecture.md` (Section 2.2: Containerization) and `local-development.md`.

**2. Goal:**
To create a Dockerfile for the `saascript-frontend-web` application, build its Docker image, and integrate it into the `infra/docker-compose.yml` file. The containerized frontend should start successfully via Docker Compose, expose its necessary ports, and serve its static and server-side rendered content, demonstrating its ability to operate within the local Dockerized environment.

**3. Detailed Steps:**
* Step 1: **Navigate to the Web Frontend Application Directory.**
    Ensure your current working directory is `frontend/web/`.
* Step 2: **Create `Dockerfile` for the Web Frontend.**
    Create a `Dockerfile` in the `frontend/web/` directory. This Dockerfile will define the multi-stage build process for a Next.js application, including dependency installation, application building, and serving the optimized production output.
* Step 3: **Update Web Frontend `package.json` for Docker Compatibility.**
    Review and potentially adjust `frontend/web/package.json` scripts to ensure they are compatible with the Docker build process (e.g., `build` script correctly compiles for production). Ensure the `start` script runs the production build.
* Step 4: **Add Web Frontend Service to `infra/docker-compose.yml`.**
    Navigate to the monorepo root and open `infra/docker-compose.yml`. Add a new service definition for `saascript-frontend-web` that builds from the `frontend/web/` Dockerfile, exposes its default Next.js port (typically 3000), and defines any necessary dependencies (though typically minimal for a basic frontend).
* Step 5: **Install Monorepo Dependencies (Again).**
    After modifying `infra/docker-compose.yml` and potentially `frontend/web/package.json`, execute `yarn install:all` at the monorepo root to ensure all dependencies are correctly handled and linked.
* Step 6: **Build and Run All Docker Compose Services.**
    Bring down the existing infrastructure services and bring them back up, including the newly added `saascript-frontend-web` service. This will trigger the Docker image build for the frontend.
* Step 7: **Verify Containerized Web Frontend Accessibility.**
    Once the services are up, verify that the containerized Web Frontend is running and accessible by navigating to `http://localhost:3000` in your browser. Confirm that the placeholder content from `index.tsx` is displayed.
* Step 8: **Document Containerization.**
    Update `docs/local-development.md` and `docs/architecture.md` to reflect the containerization of the Web Frontend, detailing its Dockerfile and its integration into the Docker Compose setup.

**7. Guidance for Software Engineer AI (GitHub Copilot):**
* **Dockerfile Generation:** In `frontend/web/`, create a `Dockerfile`. The Dockerfile should:
    * Use a multi-stage build (e.g., one `node:18-alpine` stage for `yarn install` and `next build`, another lean `node:18-alpine` stage for serving).
    * Set `WORKDIR` to `/app`.
    * Copy `package.json`, `yarn.lock`, and install dependencies.
    * Copy source code.
    * Run `yarn build` for a production build.
    * Copy only the necessary build output and `node_modules` for production serving.
    * Define `CMD ["yarn", "start"]` to run the production Next.js app.
    * Expose port 3000.
    * Create a `.dockerignore` file in `frontend/web/` to exclude unnecessary files from the Docker build context (e.g., `node_modules`, `.next`, `.env`, build artifacts).
* **`infra/docker-compose.yml` Modification:** In `infra/docker-compose.yml`, add a new service named `saascript-frontend-web`. This service should:
    * Set `build.context` to `../frontend/web`.
    * Set `ports` to `-"3000:3000"`. (Note: If `saascript-gateway` also uses 3000, consider assigning a different port like 3003 for the frontend to avoid conflicts for simultaneous local running, e.g., `3003:3000`).
    * Use `depends_on` if the frontend needs to wait for any backend services to be ready before starting.
    * Set `environment` variables if needed (e.g., `PORT: 3000` if using a different host port mapping).
* **Command Execution:** Execute `yarn install:all` at the monorepo root. Execute `docker-compose -f infra/docker-compose.yml down` followed by `docker-compose -f infra/docker-compose.yml up -d` to rebuild and restart all services.
* **Verification:** Instruct the user to access `http://localhost:3000` via browser to confirm functionality.
