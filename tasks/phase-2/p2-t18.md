# infra(saascript-modules-projects): Containerize SaaScript Project Service

**1. Rationale:**
Containerizing the Project Management microservice (`saascript-modules-projects`) is a crucial step towards achieving a portable, consistent, and scalable development and deployment environment. By creating a Dockerfile and integrating the Project Service into the `infra/docker-compose.yml` setup, we ensure that it can be run reproducibly across different developer machines and operate independently within the local Dockerized environment. This mirrors our commitment to best practices by simplifying local development and ensuring services can interoperate within the defined infrastructure, as outlined in `architecture.md` (Section 2.2: Containerization) and `local-development.md`.

**2. Goal:**
To create a Dockerfile for the `saascript-modules-projects` microservice, build its Docker image, and integrate it into the `infra/docker-compose.yml` file. The containerized Project Service should start successfully via Docker Compose, expose its necessary ports, and respond to HTTP requests, demonstrating its ability to operate within the local Dockerized environment.

**3. Detailed Steps:**
* Step 1: **Navigate to the Project Microservice Directory.**
    Ensure your current working directory is `modules/modules/projects/`.
* Step 2: **Create `Dockerfile` for the Project Microservice.**
    Create a `Dockerfile` in the `modules/modules/projects/` directory. This Dockerfile will define the steps to build a Docker image for the NestJS Project Microservice, including dependencies, build process, and runtime environment.
* Step 3: **Update Project Microservice `package.json` for Docker Compatibility.**
    Review and potentially adjust `modules/modules/projects/package.json` scripts to ensure they are compatible with the Docker build process (e.g., `build` script correctly outputs to `dist/`). Ensure the `start:prod` script uses the compiled JavaScript.
* Step 4: **Add Project Microservice to `infra/docker-compose.yml`.**
    Navigate to the monorepo root and open `infra/docker-compose.yml`. Add a new service definition for `saascript-modules-projects` that builds from the `modules/modules/projects/` Dockerfile, exposes its dedicated port (e.g., 3002), and defines its dependencies on infrastructure services (e.g., PostgreSQL if it connects immediately, or other microservices it might depend on for initial operations).
* Step 5: **Install Monorepo Dependencies.**
    After modifying `infra/docker-compose.yml` and potentially `modules/modules/projects/package.json`, execute `yarn install:all` at the monorepo root to ensure all dependencies are correctly handled and linked.
* Step 6: **Build and Run All Docker Compose Services.**
    Bring down the existing infrastructure services and bring them back up, including the newly added `saascript-modules-projects` service. This will trigger the Docker image build for the Project Service.
* Step 7: **Verify Containerized Project Microservice Accessibility.**
    Once the services are up, verify that the containerized Project Microservice is running and accessible by navigating to its default local port (e.g., `http://localhost:3002`) in your browser or with `curl`. You should receive the "Hello from SaaScript Project Management Service!" message.
* Step 8: **Document Containerization for Project Service.**
    Update `docs/local-development.md` and `docs/architecture.md` to reflect the containerization of the Project Management Microservice, detailing its Dockerfile and its integration into the Docker Compose setup.

    * Copy source code.
    * Run `yarn build` (or `nest build`).
    * Copy only necessary files to the final image (`dist/`, `node_modules`, `package.json`).
    * Define `CMD` to run the compiled application (e.g., `node dist/main`).
    * Set `WORKDIR` to `/app`.
    * Expose port 3002.
    * Create a `.dockerignore` file to exclude unnecessary files.
* **`infra/docker-compose.yml` Modification:** In `infra/docker-compose.yml`, add a new service named `saascript-modules-projects`. This service should:
    * Set `build.context` to `../modules/modules/projects`.
    * Set `ports` to `-"3002:3002"`.
    * Use `depends_on` if the project service has hard dependencies on other infrastructure services (e.g., `postgres`, `redis`, `rabbitmq`, etc.).
    * Set `environment` variables if needed (e.g., `PORT: 3002`).
* **Command Execution:** Execute `yarn install:all` at the monorepo root. Execute `docker-compose -f infra/docker-compose.yml down` followed by `docker-compose -f infra/docker-compose.yml up -d` to rebuild and restart all services.
