# infra: Setup Local RabbitMQ (Docker Compose)

**1. Rationale:**
RabbitMQ is the chosen message broker for asynchronous task queuing and reliable point-to-point message delivery within the SaaScript microservices architecture. Configuring and provisioning a local RabbitMQ instance within the `infra/` directory via Docker Compose is essential. This enables developers to immediately work on features requiring asynchronous communication, such as notifications, background processing, and inter-service messaging, laying the groundwork for robust, decoupled services as outlined in `architecture.md` (Section 4.2: Asynchronous Communication) and `local-development.md`.

**2. Goal:**
To successfully integrate a RabbitMQ message broker service into the existing `infra/docker-compose.yml` file. This includes defining the RabbitMQ container with its necessary ports (AMQP and management UI) and basic credentials, ensuring it starts automatically with the other infrastructure services via Docker Compose, and is accessible for both application connectivity and administrative monitoring.

**3. Detailed Steps:**
* Step 1: **Navigate to the SaaScript Monorepo Root.**
    Ensure your current working directory is the root of the `saascript/` monorepo clone.
* Step 2: **Add RabbitMQ Service to `infra/docker-compose.yml`.**
    Open the `infra/docker-compose.yml` file and add a new service definition for RabbitMQ. Configure it to use a suitable RabbitMQ image (preferably one with the management plugin), expose its AMQP port (5672) and HTTP management dashboard port (15672), and set default user credentials.
* Step 3: **Restart Docker Compose Services to Apply Changes.**
    Bring down the existing infrastructure services and bring them back up to include the newly added RabbitMQ service.
* Step 4: **Verify RabbitMQ Container Status and Accessibility.**
    Confirm that the RabbitMQ container is running and healthy via Docker Compose status commands. Then, access the RabbitMQ Management Dashboard via your web browser to verify its UI is available and you can log in with the configured credentials.
* Step 5: **Document Local RabbitMQ Setup.**
    Update `docs/local-development.md` to include instructions for accessing the RabbitMQ Management Dashboard and provide guidance on how applications will connect to RabbitMQ from the host machine or from other Docker containers within the same network.
    Update `docs/architecture.md` under the "Asynchronous Communication" section to confirm RabbitMQ's role and its local setup.

**4. Acceptance Criteria / Definition of Done:**
* [ ] The `rabbitmq` service definition is successfully added to the `infra/docker-compose.yml` file.
* [ ] The `rabbitmq` service uses an appropriate image (e.g., `rabbitmq:3-management-alpine`) and exposes ports `5672:5672` (AMQP) and `15672:15672` (Management UI).
* [ ] Default user (`RABBITMQ_DEFAULT_USER`) and password (`RABBITMQ_DEFAULT_PASS`) environment variables are configured in the `rabbitmq` service definition in `docker-compose.yml`.
* [ ] All Docker Compose services, including RabbitMQ, successfully start without errors.
* [ ] The RabbitMQ Management Dashboard is accessible at `http://localhost:15672` from the host machine's browser, and login is successful.
* [ ] `docs/local-development.md` is updated with instructions for accessing the RabbitMQ Management Dashboard and guidance on application connectivity.
* [ ] `docs/architecture.md` is updated to confirm RabbitMQ's integration and its purpose for asynchronous communication.

* Docker or Podman installed.

**7. Guidance for Software Engineer AI (GitHub Copilot):**
* **File Modification:** Locate the `infra/docker-compose.yml` file. Insert the `rabbitmq` service definition into the `services:` section.
* **RabbitMQ Service Definition:**
    * Use `image: "rabbitmq:3-management-alpine"`.
    * Set `ports:` to expose `5672` and `15672`.
    * Define `environment:` variables for `RABBITMQ_DEFAULT_USER` and `RABBITMQ_DEFAULT_PASS` with secure default values.
    * Optionally, `restart: always`.
    * Example snippet for `docker-compose.yml`:
        ```yaml
          rabbitmq:
            image: "rabbitmq:3-management-alpine"
            hostname: rabbitmq # Use a consistent hostname for inter-container communication
            ports:
              - "5672:5672" # AMQP protocol port
              - "15672:15672" # Management UI port
            environment:
              RABBITMQ_DEFAULT_USER: "saascript_user" # Replace with a strong password in .env if desired later
              RABBITMQ_DEFAULT_PASS: "saascript_pass" # Replace with a strong password in .env if desired later
            restart: always
        ```
* **Command Execution:** Execute `docker-compose -f infra/docker-compose.yml down` followed by `docker-compose -f infra/docker-compose.yml up -d` from the monorepo root.
* **Verification:** Instruct the user to check `docker-compose -f infra/docker-compose.yml ps` and then open `http://localhost:15672` in their web browser and attempt to log in with the configured credentials (`saascript_user`/`saascript_pass`).
