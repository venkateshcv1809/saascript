# chore: Configure Husky and Lint-Staged for Code Quality

**1. Rationale:**
Enforcing consistent code style and preventing common errors early in the development cycle is crucial for maintaining high code quality across the SaaScript monorepo. Integrating Husky Git hooks with Lint-Staged allows for automated execution of linting and formatting checks specifically on staged files before they are committed. This ensures that only code adhering to the project's `code-style-guidelines.md` enters the codebase, significantly reducing review cycles, improving maintainability, and fostering a disciplined development workflow for all team members (human and AI).

**2. Goal:**
To successfully install and configure Husky and Lint-Staged in the SaaScript monorepo. This involves setting up a `pre-commit` Git hook via Husky to automatically run ESLint (with auto-fix) and Prettier (with auto-format) on all staged TypeScript, JavaScript, and JSON files, ensuring code quality checks are performed before every commit.

**3. Detailed Steps:**
* Step 1: **Navigate to the SaaScript Monorepo Root.**
    Ensure your current working directory is the root of the `saascript/` monorepo clone.
* Step 2: **Install Husky and Lint-Staged as Development Dependencies.**
    Install `husky` and `lint-staged` as dev dependencies at the monorepo root using Yarn.
* Step 3: **Initialize Husky and Add `pre-commit` Hook.**
    Initialize Husky within the monorepo, which sets up the `.husky/` directory. Then, add a `pre-commit` Git hook to the `.husky/pre-commit` file that executes `npx lint-staged`. This newly created hook file must then be staged and committed to Git.
* Step 4: **Configure Lint-Staged in Root `package.json`.**
    Add the `lint-staged` configuration to the `package.json` file at the monorepo root. This configuration will define the file patterns to check (e.g., `*.{ts,tsx,js,jsx,json,md,yaml}`) and specify the commands to run (`eslint --fix`, `prettier --write`) on matched staged files.
* Step 5: **Test the Husky and Lint-Staged Configuration.**
    Perform a test to verify the `pre-commit` hook's functionality. This involves making a small, intentional style violation or linting error in a staged file and then attempting to commit the change. The hook should automatically attempt to fix the issues, and the commit should either proceed (if fixable) or be aborted (if unfixable errors remain).
* Step 6: **Document Husky and Lint-Staged Setup.**
    Update the `docs/development-workflow.md` and `docs/code-style-guidelines.md` files to clearly describe the role of Husky and Lint-Staged in the development process, including how they enforce code quality and style automatically before commits.

**4. Acceptance Criteria / Definition of Done:**
* [ ] `husky` and `lint-staged` are installed as dev dependencies at the monorepo root.
* [ ] Husky is initialized, and a `.husky/` directory exists with a staged `pre-commit` hook file.
* [ ] The `pre-commit` hook successfully executes `npx lint-staged`.
* [ ] The root `package.json` contains a `lint-staged` configuration that targets `*.{ts,tsx,js,jsx,json,md,yaml}` files.
* [ ] The `lint-staged` configuration executes `eslint --fix` and `prettier --write` on the matched staged files.
* [ ] Committing a staged file with a fixable linting/formatting issue automatically fixes the issue, and the commit proceeds cleanly.
* [ ] Committing a staged file with an unfixable linting error (if ESLint is configured to fail on it) is prevented by the `pre-commit` hook.
* [ ] `docs/development-workflow.md` is updated to describe the `pre-commit` hook and `lint-staged` integration.

**7. Guidance for Software Engineer AI (GitHub Copilot):**

* **Husky Setup:** Execute `npx husky install` and `npx husky add .husky/pre-commit "npx lint-staged"`. Then, `git add .husky/pre-commit`.

    ```json
    {
      "lint-staged": {
        "*.{ts,tsx,js,jsx,json,md,yaml}": [
          "eslint --fix",
          "prettier --write"
        ]
      }
    }
    ```
