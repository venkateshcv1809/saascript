# infra: Setup Local Development Environment with Docker Compose

**1. Rationale:**
This task is fundamental for the entire SaaScript project as it establishes the complete local development environment. This includes creating and populating the `infra/docker-compose.yml` file, installing all necessary monorepo dependencies, and spinning up the core shared infrastructure services (PostgreSQL, Redis, RabbitMQ, Kafka, DynamoDB, HashiCorp Vault). Without these foundational elements, no further microservice development, application building, or testing can proceed. This setup ensures consistency across all development machines and provides a robust, predictable platform for iterative development, directly addressing the need for strict alignment across the AI team and minimizing unexpected deviations.

**2. Goal:**
To successfully create the `infra/docker-compose.yml` file, install all monorepo dependencies, and set up/run all essential local infrastructure services for the SaaScript monorepo using Docker Compose (or Podman Compose), ensuring all components, especially HashiCorp Vault in its developer mode, are fully operational and accessible, and updating core project documentation (`saascript.md` and main `README.md`) to reflect this setup.

**3. Detailed Steps:**
* Step 1: **Ensure Monorepo Root Directory Context.**
    Verify the current working directory is the root of the `saascript/` monorepo clone.
* Step 2: **Create `infra/docker-compose.yml` and Define Core Infrastructure Services.**
    Create the `infra/` directory if it doesn't exist, and then create the `docker-compose.yml` file inside it. Populate this file with the specified service definitions for PostgreSQL, Redis, RabbitMQ, Kafka (with Zookeeper), DynamoDB Local, and HashiCorp Vault, including Vault's developer mode configuration.
* Step 3: **Create `infra/.env` File and Add to Monorepo `.gitignore`.**
    Create a `.env` file specifically within the `infra/` directory to store sensitive environment variables for Docker Compose services. Ensure this specific path (`infra/.env`) is added to the monorepo's root `.gitignore` file to prevent accidental commitment of sensitive data.
* Step 4: **Install Monorepo Dependencies.**
    Execute the command to install all project dependencies for the entire monorepo using Yarn Workspaces, which will install dependencies for all current and future packages within the monorepo.
* Step 5: **Start Core Infrastructure Services via Docker Compose.**
    From the monorepo root directory, initiate the startup of all defined infrastructure services using Docker Compose.
* Step 6: **Verify Docker Compose Service Status.**
    Confirm that all Docker Compose containers are running and healthy.
* Step 7: **Login to HashiCorp Vault (Developer Mode).**
    Configure the `VAULT_ADDR` environment variable and then log in to Vault using the predetermined developer root token (`myroot`).
* Step 8: **Verify Vault Status.**
    Confirm that Vault reports as unsealed and initialized.
* Step 9: **Verify Other Service Port Accessibility.**
    Perform basic checks to confirm that other infrastructure services (PostgreSQL, Redis, RabbitMQ, Kafka, DynamoDB) are listening on their expected ports.
* Step 10: **Document the Setup in `saascript.md`.**
    Update the "Technology Stack Overview" section within `saascript.md` to describe how Docker Compose is used for local development and list the services it orchestrates.
* Step 11: **Update Main Repository `README.md` for Local Development.**
    Add a dedicated "Local Development Setup" section to the main `saascript` repository's `README.md` with clear instructions on how to bring up and shut down the local development environment using the new monorepo scripts (to be defined in P1-T2).

**4. Acceptance Criteria / Definition of Done:**
* [ ] The `infra/` directory is created at the monorepo root.
* [ ] The `infra/docker-compose.yml` file is created and contains the definitions for PostgreSQL, Redis, RabbitMQ, Kafka (with Zookeeper), DynamoDB Local, and HashiCorp Vault, including Vault's developer mode configuration.
* [ ] An `infra/.env` file is present for sensitive environment variables, and its path (`infra/.env`) is correctly added to the monorepo's `.gitignore`.
* [ ] All monorepo dependencies are successfully installed via `yarn install:all`.
* [ ] All core infrastructure services are successfully launched and running via `docker-compose -f infra/docker-compose.yml up -d`.
* [ ] The `docker-compose -f infra/docker-compose.yml ps` command returns an 'Up' status for all expected containers.
* [ ] HashiCorp Vault is accessible and verifiable as unsealed in developer mode (e.g., `vault status` confirms `Sealed: false`, `Initialized: true` after login).
* [ ] The developer can successfully log in to Vault using the `myroot` token.
* [ ] There are no port conflicts with existing applications on the local machine for any of the infrastructure services.
* [ ] Basic connectivity to at least one other service (e.g., `psql -h localhost -p 5432 -U postgres -d saascript_db`) is successful.
* [ ] The `local-development.md` guide is reviewed and confirmed to accurately reflect these setup steps (no specific update needed for this task, just a review).
* [ ] The `saascript.md` (Project Overview) is updated to include a clear description of the local Docker Compose setup under its "Technology Stack Overview" section.
* [ ] The main `saascript` repository's `README.md` is updated with a dedicated "Local Development Setup" section, including instructions for starting and stopping the environment.

**5. Dependencies / Pre-requisites:**
* Existing SaaScript monorepo clone (initial setup).
* Node.js (v18.x or later) and Yarn installed globally.
* Docker or Podman (with Docker Compose or Podman Compose installed and configured).
* HashiCorp Vault CLI (installed and added to PATH for `vault` commands - for verification/interaction beyond basic startup).
