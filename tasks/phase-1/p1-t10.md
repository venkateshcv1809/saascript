
# infra(saascript-gateway): Containerize SaaScript API Gateway

**1. Rationale:**
Containerizing the SaaScript API Gateway is a crucial step towards achieving a portable, consistent, and scalable development and deployment environment. By creating a Dockerfile and integrating the gateway into the `infra/docker-compose.yml` setup, we ensure that the API Gateway can be run reproducibly across different developer machines and aligns with our microservices architecture's principles of independent deployment. This also simplifies the local development workflow by allowing the gateway to run alongside other infrastructure services, as outlined in `architecture.md` (Section 2.2: Containerization) and `local-development.md`.

**2. Goal:**
To create a Dockerfile for the `saascript-gateway` service, build its Docker image, and integrate it into the `infra/docker-compose.yml` file. The containerized gateway should start successfully via Docker Compose, expose its necessary ports, and respond to HTTP requests, demonstrating its ability to operate within the local Dockerized environment.

**3. Detailed Steps:**
* Step 1: **Navigate to the API Gateway Service Directory.**
    Ensure your current working directory is `modules/gateway/`.
* Step 2: **Create `Dockerfile` for the API Gateway.**
    Create a `Dockerfile` in the `modules/gateway/` directory. This Dockerfile will define the steps to build a Docker image for the NestJS API Gateway, including dependencies, build process, and runtime environment.
* Step 3: **Update API Gateway `package.json` for Docker Compatibility.**
    Review and potentially adjust `modules/gateway/package.json` scripts to ensure they are compatible with the Docker build process (e.g., `build` script correctly outputs to `dist/`). Ensure the `start:prod` script uses the compiled JavaScript.
* Step 4: **Add API Gateway Service to `infra/docker-compose.yml`.**
    Navigate to the monorepo root and open `infra/docker-compose.yml`. Add a new service definition for `saascript-gateway` that builds from the `modules/gateway/` Dockerfile, exposes its port (e.g., 3000), and defines its dependencies (e.g., PostgreSQL, Redis if it needed direct access, though for a basic gateway, only the port is crucial initially).
* Step 5: **Install Monorepo Dependencies (Again).**
    After modifying `infra/docker-compose.yml` and potentially `modules/gateway/package.json`, execute `yarn install:all` at the monorepo root to ensure all dependencies are correctly handled and linked.
* Step 6: **Build and Run All Docker Compose Services.**
    Bring down the existing infrastructure services and bring them back up, including the newly added `saascript-gateway` service. This will trigger the Docker image build for the gateway.
* Step 7: **Verify Containerized API Gateway Accessibility.**
    Once the services are up, verify that the containerized API Gateway is running and accessible by navigating to `http://localhost:3000` in your browser or with `curl`. You should receive the "Hello from SaaScript API Gateway!" message.
* Step 8: **Document Containerization.**
    Update `docs/local-development.md` and `docs/architecture.md` to reflect the containerization of the API Gateway, detailing its Dockerfile and its integration into the Docker Compose setup.

**4. Acceptance Criteria / Definition of Done:**
* [ ] A `Dockerfile` is created in `modules/gateway/` for the API Gateway.

* [ ] `yarn install:all` (from monorepo root) successfully processes changes related to the gateway's Docker setup.
* [ ] `docker-compose -f infra/docker-compose.yml up -d` successfully builds and starts the `saascript-gateway` container along with other infrastructure services.

    * Copy `package.json` and `yarn.lock`, install dependencies.
    * Copy source code.
    * Run `yarn build` (or `nest build`).
    * Copy only necessary files to the final image (`dist/`, `node_modules`, `package.json`).

    * Set `build.context` to `../modules/gateway`.
    * Set `ports` to `-"3000:3000"`.
    * Use `depends_on` if the gateway has hard dependencies on other services (e.g., `postgres`, `redis`, etc. from P1-T1).
    * Set `environment` variables if needed (e.g., `PORT: 3000`).
* **Command Execution:** Execute `yarn install:all` at the monorepo root. Execute `docker-compose -f infra/docker-compose.yml down` followed by `docker-compose -f infra/docker-compose.yml up -d` to rebuild and restart all services.
