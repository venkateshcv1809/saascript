# feat(saascript-frontend-web): Implement Authenticated Dashboard View

**1. Rationale:**
The authenticated dashboard view serves as the primary landing page for logged-in users, providing personalized content and access to core application features. Implementing this view in `saascript-frontend-web` is crucial for completing the end-to-end authentication flow initiated in P2-T12. It acts as a critical validation point for token management and protected routing via the API Gateway. This task reinforces user experience, confirms the secure interaction between frontend and backend, and demonstrates the successful culmination of our authentication infrastructure, aligning with the project's goal of building a functional and secure application.

**2. Goal:**
To develop a responsive, authenticated dashboard view within the `saascript-frontend-web` application that is accessible only to logged-in users. This includes:
* Implementing client-side logic to ensure the page is protected and redirects unauthenticated users.
* Fetching authenticated user profile data from the API Gateway's protected endpoint (`/auth/profile`).
* Displaying relevant user information on the dashboard.
* Implementing a functional logout mechanism that invalidates the user's session/token client-side and redirects them to the login page.

**3. Detailed Steps:**
* Step 1: **Navigate to the Web Frontend Application Directory.**
    Ensure your current working directory is `frontend/web/`.
* Step 2: **Refine Dashboard Page/Component.**
    Expand upon the basic protected page created in P2-T12 (e.g., `frontend/web/pages/dashboard.tsx`). This page will serve as the authenticated dashboard.
* Step 3: **Implement Authentication Guard for Dashboard.**
    Develop or refine client-side logic (e.g., a custom React hook, a higher-order component, or direct `useEffect` logic) within `dashboard.tsx` to check for an authenticated user. If no valid token is found, redirect the user to the login page (`/login`).
* Step 4: **Fetch Authenticated User Profile Data.**
    Within the dashboard component, implement logic to make an authenticated GET request to the API Gateway's protected user profile endpoint (e.g., `http://localhost:3000/auth/profile`). Ensure the JWT `accessToken` is included in the `Authorization: Bearer` header.
* Step 5: **Display User Information.**
    Once user profile data is successfully fetched, display relevant information (e.g., email, user ID) on the dashboard UI.
* Step 6: **Implement Logout Functionality.**
    Add a "Logout" button or link to the dashboard. Upon click, implement client-side logic to:
    * Clear the stored JWTs (e.g., remove from `localStorage`).
    * Redirect the user to the login page (`/login`).
    * *Note:* This task focuses on client-side logout. Server-side token invalidation will be part of future security enhancements if refresh tokens are persisted.
* Step 7: **Install Monorepo Dependencies.**
    Execute the monorepo-wide dependency installation command if any new packages are introduced.
* Step 8: **Build and Run the Web Frontend Application.**
    Build the `saascript-frontend-web` and then start it in development mode.
* Step 9: **Test Authenticated Dashboard End-to-End.**
    Perform end-to-end tests:
    * Log in successfully. Verify redirection to the dashboard and display of user data.
    * Attempt to access the dashboard directly without logging in. Verify redirection to the login page.
    * Log out. Verify token removal and redirection.
    * Test with an expired/invalid token (if applicable for `localStorage` checks) and verify redirection.
* Step 10: **Document Authenticated Dashboard.**
    Update `docs/frontend.md` to detail the authenticated dashboard view, how it fetches and displays user data, and the logout mechanism.

**7. Guidance for Software Engineer AI (GitHub Copilot):**
* **Dashboard Component/Page:** Refine `frontend/web/pages/dashboard.tsx`.
* **Authentication Guard (Client-Side):**
    * In `dashboard.tsx` (or a custom hook used by it), use `useEffect` to check for `localStorage.getItem('accessToken')`.
    * If `null` or invalid, use `Router.push('/login')` from `next/router` to redirect.
    * Consider adding a loading state while checking authentication.
* **Fetch User Profile:**
    * Inside the dashboard, use `fetch` or `axios` to call `http://localhost:3000/auth/profile`.
    * Include the `Authorization: Bearer <token>` header, retrieving the token from `localStorage`.
    * Handle success (update state with user data) and error (display message, redirect).
* **Display User Data:** Render the fetched user's `email` and `id` (or other relevant fields) on the page.
* **Logout Button/Logic:**
    * Add a button or link with an `onClick` handler.
    * The handler should call `localStorage.removeItem('accessToken')` (and `refreshToken`).
    * Then, `Router.push('/login')`.
* **Command Execution & Verification:** Instruct the user to run `yarn workspace saascript-frontend-web dev` (after ensuring backend services are up). Guide them through manual testing:
    1.  Log in via `/login`.
    2.  Verify redirection to `/dashboard` and user data display.
    3.  Open a new incognito window and try to navigate directly to `/dashboard`. It should redirect to `/login`.
    4.  Log out from the dashboard and verify redirection.
