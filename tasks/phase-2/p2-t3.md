# infra: Setup Local Apache Kafka (Docker Compose)

**1. Rationale:**
Apache Kafka is the chosen event streaming platform for high-throughput, real-time data pipelines and event-driven architectures within the SaaScript microservices. Configuring and provisioning a local Kafka cluster (along with its dependency, Apache Zookeeper) via Docker Compose is essential. This enables developers to immediately work on features requiring event-based communication, such as real-time analytics, audit logging, and reactive service patterns, laying the groundwork for a scalable and resilient system as outlined in `architecture.md` (Section 4.2: Asynchronous Communication) and `local-development.md`.

**2. Goal:**
To successfully integrate Apache Zookeeper and Apache Kafka services into the existing `infra/docker-compose.yml` file. This includes defining both containers with their necessary ports and configurations, ensuring they start automatically with the other infrastructure services via Docker Compose, and are accessible for application connectivity.

**3. Detailed Steps:**
* Step 1: **Navigate to the SaaScript Monorepo Root.**
    Ensure your current working directory is the root of the `saascript/` monorepo clone.
* Step 2: **Add Apache Zookeeper Service to `infra/docker-compose.yml`.**
    Open the `infra/docker-compose.yml` file and add a new service definition for Zookeeper. This is a prerequisite for Kafka. Configure it to expose its client port.
* Step 3: **Add Apache Kafka Service to `infra/docker-compose.yml`.**
    Add a new service definition for Kafka, ensuring it depends on the Zookeeper service. Configure Kafka with its broker ID, advertised listeners (pointing to `localhost` and the internal Docker network name), and connect it to the Zookeeper instance. Expose the Kafka broker port (9092).
* Step 4: **Restart Docker Compose Services to Apply Changes.**
    Bring down the existing infrastructure services and bring them back up to include the newly added Zookeeper and Kafka services.
* Step 5: **Verify Kafka and Zookeeper Container Status and Accessibility.**
    Confirm that both the Zookeeper and Kafka containers are running and healthy via Docker Compose status commands. Perform a basic connectivity test to the Kafka broker (e.g., using `kafkacat` or a simple Kafka client in a test script) to ensure it's listening and responsive.
* Step 6: **Document Local Kafka Setup.**
    Update `docs/local-development.md` to include instructions for verifying the Kafka setup and provide guidance on how applications will connect to Kafka from the host machine or from other Docker containers within the same network.
    Update `docs/architecture.md` under the "Asynchronous Communication" section to confirm Kafka's role and its local setup.

**4. Acceptance Criteria / Definition of Done:**
* [ ] The `zookeeper` service definition is successfully added to the `infra/docker-compose.yml` file, exposing port `2181:2181`.
* [ ] The `kafka` service definition is successfully added to the `infra/docker-compose.yml` file.
* [ ] The `kafka` service is configured to depend on `zookeeper` (`depends_on`).
* [ ] `kafka` is configured with necessary environment variables (e.g., `KAFKA_BROKER_ID`, `KAFKA_ZOOKEEPER_CONNECT`, `KAFKA_ADVERTISED_LISTENERS` for both `PLAINTEXT://localhost:9092` and internal Docker network).
* [ ] The `kafka` service exposes port `9092:9092`.
* [ ] All Docker Compose services, including Zookeeper and Kafka, successfully start without errors.
* [ ] `docker-compose -f infra/docker-compose.yml ps` shows `Up` status for both `zookeeper` and `kafka` containers.

**7. Guidance for Software Engineer AI (GitHub Copilot):**
* **File Modification:** Locate the `infra/docker-compose.yml` file. Insert the `zookeeper` and `kafka` service definitions into the `services:` section.
* **Zookeeper Service Definition:**
    ```yaml
      zookeeper:
        image: confluentinc/cp-zookeeper:7.0.1
        hostname: zookeeper
        ports:
          - "2181:2181"
        environment:
          ZOOKEEPER_CLIENT_PORT: 2181
          ZOOKEEPER_TICK_TIME: 2000
        restart: always
    ```
* **Kafka Service Definition:**
    ```yaml
      kafka:
        image: confluentinc/cp-kafka:7.0.1
        hostname: kafka
        ports:
          - "9092:9092"
        environment:
          KAFKA_BROKER_ID: 1
          KAFKA_ZOOKEEPER_CONNECT: zookeeper:2181
          KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://localhost:9092,PLAINTEXT_INTERNAL://kafka:29092
          KAFKA_LISTENER_SECURITY_PROTOCOL_MAP: PLAINTEXT:PLAINTEXT,PLAINTEXT_INTERNAL:PLAINTEXT
          KAFKA_INTER_BROKER_LISTENER_NAME: PLAINTEXT_INTERNAL
          KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
          KAFKA_GROUP_INITIAL_REBALANCE_DELAY_MS: 0
        depends_on:
          - zookeeper
        restart: always
    ```
* **Command Execution:** Execute `docker-compose -f infra/docker-compose.yml down` followed by `docker-compose -f infra/docker-compose.yml up -d` from the monorepo root.
* **Verification:** Instruct the user to check `docker-compose -f infra/docker-compose.yml ps`. For Kafka connectivity, suggest a simple test:
    * Install `kafkacat` (if not already installed).
    * `echo "test message" | kafkacat -b localhost:9092 -t test_topic -P` (to produce)
    * `kafkacat -b localhost:9092 -t test_topic -C` (to consume, then produce a message in another terminal)
