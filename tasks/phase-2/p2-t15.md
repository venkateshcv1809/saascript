# chore(saascript-libs-authz): Implement Shared Backend Authorization Module (NestJS)

**1. Rationale:**
Server-side authorization is the definitive control layer for determining what an authenticated user is permitted to do within the SaaScript system. While client-side authorization (P2-T14) enhances UX, it is not a substitute for robust backend enforcement. This task establishes a consistent, reusable server-side authorization framework as a dedicated NestJS shared library (`modules/libs/authz/`). This module will centralize permission management, define how access control policies are implemented and checked (e.g., using a policy-based approach or a backend adaptation of CASL's `Ability` concept), and provide decorators or guards for easily protecting API endpoints in all microservices. This is paramount for data integrity, security, and adherence to best practices in microservices architecture.

**2. Goal:**
To successfully create a shared NestJS module (`AuthzModule`) within `modules/libs/authz/` that provides a standardized backend authorization framework. This includes:
* Setting up its dedicated project structure.
* Defining how user roles/permissions are represented and loaded (e.g., from the JWT payload or by querying the `auth_service`).
* Implementing custom NestJS guards and/or decorators to enforce authorization checks on controllers/routes.
* Providing a mechanism to define and evaluate authorization "abilities" or policies for various actions and resources.
* Ensuring the module is correctly recognized as a Yarn workspace within the monorepo, ready for injection into individual microservices.

**3. Detailed Steps:**
* Step 1: **Navigate to the `modules/libs/` Directory.**
    Ensure your current working directory is `modules/libs/` at the monorepo root.
* Step 2: **Create the `authz/` Module Directory.**
    Create the `authz/` directory inside `modules/libs/`. This will be the root for the shared authorization module.
* Step 3: **Initialize Node.js Project and Install Dependencies.**
    Initialize a new Node.js project within `modules/libs/authz/`. Install necessary NestJS packages (`@nestjs/common`, `@nestjs/core`), and potentially a library if a specific authorization pattern like `casl` is chosen for backend (e.g., `@casl/ability`). Install TypeScript dev dependencies.
* Step 4: **Create `tsconfig.json` for the Authorization Module.**
    Create a `tsconfig.json` file inside `modules/libs/authz/` to configure TypeScript compilation for this shared library.
* Step 5: **Create `src/` Directory and Authorization Module Files.**
    Create the `src/` directory within `modules/libs/authz/` and populate it with:
    * `authz.module.ts`: The main NestJS module.
    * `abilities.guard.ts`: A custom NestJS guard that enforces authorization based on defined abilities/policies.
    * `check-abilities.decorator.ts`: A custom NestJS decorator (e.g., `@CheckAbilities()`) to mark controller methods with required permissions.
    * `ability.factory.ts`: A service or factory responsible for building a user's `Ability` instance (or similar policy object) based on their roles/payload.
    * `constants.ts` / `types.ts`: For defining permission-related enums, interfaces, or types.
* Step 6: **Update Authorization Module `package.json` Scripts.**
    Modify the `package.json` within `modules/libs/authz/` to include necessary scripts, particularly `build`.
* Step 7: **Update Monorepo Root `package.json` Workspaces.**
    Add `modules/libs/authz` to the `workspaces` array in the monorepo's root `package.json` (`saascript/package.json`) to ensure Yarn recognizes this new shared module.
* Step 8: **Install Monorepo Dependencies.**
    Execute `yarn install:all` at the monorepo root to ensure all new dependencies for the authorization module are installed and cross-linked correctly within the monorepo.
* Step 9: **Build the Shared Authorization Module.**
    Build the newly created `saascript-libs-authz` module to ensure it compiles correctly.
* Step 10: **Document Backend Authorization Strategy.**
    Update `docs/architecture.md` (under "Security" and/or "Module Design Principles") and `docs/security.md` to detail the backend authorization strategy. Explain the role of this shared module, how it interacts with authenticated user context (from JWT, via Gateway), and how microservices will utilize its guards/decorators to protect their endpoints.

* **`tsconfig.json` Generation:** Create and populate `modules/libs/authz/tsconfig.json` for a NestJS library.
* **Authorization Files:**
    * **`authz.module.ts`:** Main NestJS module.
    * **`constants.ts` (or `types.ts`):** Define `Action` enum (e.g., `Manage`, `Create`, `Read`, `Update`, `Delete`) and `Subject` enum (e.g., `User`, `Project`, `All`).
    * **`ability.factory.ts`:** Create a `AbilityFactory` service. It should have a method `defineAbilitiesForUser(user: UserContext)` that takes a user object (e.g., derived from JWT payload, containing roles) and returns a `PureAbility` instance from `@casl/ability` using `defineAbility`.
    * **`check-abilities.decorator.ts`:** Create `@CheckAbilities` custom decorator. This decorator will store metadata (e.g., required `Action` and `Subject`) on the route handler using `@SetMetadata(CHECK_ABILITY_KEY, permissions)`.
    * **`abilities.guard.ts`:** Create `AbilitiesGuard` class that implements `CanActivate`.
        * Inject `Reflector` from `@nestjs/core`.
        * Inject `AbilityFactory`.
        * In `canActivate`, get required abilities from route metadata using `Reflector.getAllAndOverride`.
        * Retrieve the authenticated `user` from the request (e.g., `req.user` populated by JWT Passport in Gateway/Auth Service).
        * Use `AbilityFactory` to create the user's `Ability`.
        * Call `ability.can(action, subject)` for each required permission. Return `true` if all checks pass, `false` otherwise.
