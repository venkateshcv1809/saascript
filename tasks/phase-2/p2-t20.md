# feat(saascript-modules-projects): Implement CRUD for Projects

**1. Rationale:**
Implementing Create, Read, Update, and Delete (CRUD) functionalities for Project entities is the cornerstone of the `saascript-modules-projects` microservice. This task directly addresses the core business logic, enabling users to manage their projects within the SaaScript platform. By developing these APIs, we validate the complete backend stack, including PostgreSQL integration (P2-T19), standardized error handling (P2-T6), input validation (P2-T7), and critically, server-side authorization (P2-T15). This ensures that only authorized users can perform operations on projects they own or have permission for, delivering secure and functional core features in line with architectural best practices.

**2. Goal:**
To develop and secure the core CRUD API endpoints within the `saascript-modules-projects` microservice for managing `Project` entities. This includes:
* Defining specific DTOs for creating, updating, and retrieving projects.
* Implementing validation rules for project data.
* Integrating with the PostgreSQL database (via `saascript-libs-database-postgres`) to persist and retrieve project data.
* Protecting these endpoints using the shared backend authorization module (`saascript-libs-authz`), ensuring projects are associated with their `ownerId` from the authenticated user context.
* Exposing these endpoints via the API Gateway.
* Ensuring all responses and errors adhere to defined standards.

**3. Detailed Steps:**
* Step 1: **Navigate to the Project Microservice Directory.**
    Ensure your current working directory is `modules/modules/projects/`.
* Step 2: **Create Project-Specific DTOs.**
    Define Data Transfer Objects (DTOs) for creating new projects (e.g., `CreateProjectDto`), updating existing projects (e.g., `UpdateProjectDto`), and for the API responses (e.g., `ProjectResponseDto`). Apply `class-validator` decorators (P2-T7) to `CreateProjectDto` and `UpdateProjectDto`.
* Step 3: **Implement Project Service.**
    Create `modules/modules/projects/src/projects/projects.service.ts`. This service will encapsulate the business logic for CRUD operations, interacting with the TypeORM `ProjectEntity` repository to save, retrieve, update, and delete projects. Ensure logic considers the `ownerId` for all operations.
* Step 4: **Implement Project Controller.**
    Create `modules/modules/projects/src/projects/projects.controller.ts`. This controller will expose the API endpoints for project CRUD operations.
    * **Implement `POST /projects`:** For creating new projects. It should accept `CreateProjectDto`, retrieve `ownerId` from the authenticated user context (via `req.user` or `@User()` decorator), and pass it to the service.
    * **Implement `GET /projects`:** For retrieving all projects accessible to the authenticated user.
    * **Implement `GET /projects/:id`:** For retrieving a single project by ID.
    * **Implement `PATCH /projects/:id` or `PUT /projects/:id`:** For updating projects. It should accept `UpdateProjectDto` and ensure the requesting user is the `owner` or has appropriate permissions.
    * **Implement `DELETE /projects/:id`:** For deleting projects, with similar authorization checks.
* Step 5: **Integrate Shared Backend Authorization.**
    Import and apply the `AbilitiesGuard` and `@CheckAbilities` decorator from `saascript-libs-authz` (P2-T15) to the `ProjectsController` methods. Define granular permissions (e.g., `can Create Project`, `can Read Project`, `can Update Project`, `can Delete Project`, potentially scoped to `own` projects).
* Step 6: **Update Project Module.**
    Create or update `modules/modules/projects/src/projects/projects.module.ts`. This module should register `TypeOrmModule.forFeature([ProjectEntity])`, import the shared `AuthzModule` (from P2-T15), and provide the `ProjectsService` and `ProjectsController`.
* Step 7: **Configure Global Pipes/Filters for Project Service.**
    Ensure `modules/modules/projects/src/main.ts` applies the global `ValidationPipe` (P2-T7) and `AllExceptionsFilter` (P2-T6) consistently.
* Step 8: **Update API Gateway Routing.**
    Modify `modules/gateway/src/main.ts` or a relevant Gateway controller to configure proxy routing for the new `/projects` endpoints to the `saascript-modules-projects` microservice's internal URL. Ensure the authenticated user's JWT is forwarded and their context is available to the Project Service.
* Step 9: **Install Monorepo Dependencies.**
    Execute the monorepo-wide dependency installation command.
* Step 10: **Build and Run Services.**
    Build and start `saascript-gateway`, `saascript-auth-service`, and `saascript-modules-projects` in development mode.
* Step 11: **Test CRUD Endpoints End-to-End.**
    Use an API client (e.g., Postman) to:
    * Register and log in a user via the Gateway (`/auth/register`, `/auth/login`).
    * Use the obtained JWT to:
        * Create a new project (`POST /projects`). Verify `201 Created` and data persistence.
        * Read projects (`GET /projects`, `GET /projects/:id`). Verify data retrieval.
        * Update a project (`PATCH /projects/:id`). Verify `200 OK` and data modification.
        * Delete a project (`DELETE /projects/:id`). Verify `204 No Content`.
    * Test with invalid inputs (P2-T7) and verify `400 Bad Request` errors (P2-T6).
    * Test with missing/invalid tokens (P2-T11) and verify `401 Unauthorized`.
    * Test unauthorized actions (e.g., user A trying to update user B's project) and verify `403 Forbidden` (P2-T15).
* Step 12: **Document Project Management APIs.**
    Update `docs/api-contracts.md` with detailed specifications for all Project Management CRUD endpoints, including request/response DTOs, expected status codes, and specific authorization rules. Update `docs/microservices.md` and `docs/security.md` to reflect the implemented functionalities and their security implications.

* **Project Service:** Create `modules/modules/projects/src/projects/projects.service.ts`.
    * Inject `ProjectRepository` (from TypeORM, using `@InjectRepository(ProjectEntity)`).
    * Implement methods: `create(projectData: CreateProjectDto, userId: string)`, `findAll(userId: string)`, `findById(id: string, userId: string)`, `update(id: string, updateData: UpdateProjectDto, userId: string)`, `delete(id: string, userId: string)`.
    * Ensure all methods perform checks against `userId`/`ownerId` where relevant for authorization.
* **Project Controller:** Create `modules/modules/projects/src/projects/projects.controller.ts`.
    * Inject `ProjectsService`.
    * Apply `@Controller('projects')`.
    * For each CRUD method:
        * `@Post()`, `@Get()`, `@Get(':id')`, `@Patch(':id')`, `@Delete(':id')`.
        * Use `@Body()`, `@Param('id')`, `@Req()` to get data.
        * **Crucially**: Apply `@UseGuards(JwtAuthGuard)` (from Gateway's `auth` module, assuming it's exported or reused) for authentication, and **`@UseGuards(AbilitiesGuard)`** (from `saascript-libs-authz`).
        * Apply **`@CheckAbilities`** decorator to each method, defining the required action and subject (e.g., `@CheckAbilities({ action: Action.Create, subject: Subject.Project })` for POST, `@CheckAbilities({ action: Action.Read, subject: Subject.Project })` for GET, etc.).

    * Import `TypeOrmModule.forFeature([ProjectEntity])`.
    * Import `AuthzModule` from `@saascript/libs-authz`.
    * Define `ProjectsService` and `ProjectsController` as providers/controllers.
