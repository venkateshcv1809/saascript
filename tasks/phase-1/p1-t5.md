# infra: Setup Local Email Testing (MailHog)

**1. Rationale:**
For applications that send emails (e.g., for user registration, password resets, notifications), a robust local email testing solution is crucial. Sending real emails during development is inefficient, can clutter inboxes, and may lead to accidental sends. A local mail server like MailHog captures all outgoing emails, providing a web interface to inspect them, allowing developers to test email-dependent features safely and effectively without leaving the development environment. This streamlines testing for features that are vital for the SaaScript platform's user experience and ensures consistent testing practices.

**2. Goal:**
To integrate MailHog into the existing `infra/docker-compose.yml` file, ensuring it starts automatically with the other infrastructure services. This setup will redirect all application-generated emails to MailHog, making them accessible via a web-based UI for easy inspection and testing.

**3. Detailed Steps:**
* Step 1: **Navigate to the SaaScript Monorepo Root.**
    Ensure your current working directory is the root of the `saascript/` monorepo clone.
* Step 2: **Add MailHog Service to `infra/docker-compose.yml`.**
    Open the `infra/docker-compose.yml` file and add a new service definition for MailHog. Configure it to expose its SMTP port (for capturing emails) and its HTTP dashboard port (for viewing captured emails).
* Step 3: **Restart Docker Compose Services to Apply Changes.**
    Bring down the existing infrastructure services and bring them back up to include the newly added MailHog service.
* Step 4: **Verify MailHog Accessibility.**
    Once the services are up, open your web browser and navigate to the MailHog web UI URL (`http://localhost:8025`). Confirm that the MailHog dashboard loads correctly and is ready to capture emails.
* Step 5: **Document Local Email Testing Setup.**
    Update the `docs/local-development.md` to include instructions for accessing the MailHog UI and clear guidance on configuring applications to send emails to MailHog (e.g., pointing SMTP configuration to `localhost:1025` from the host or `mailhog:1025` if within the same Docker network).

**4. Acceptance Criteria / Definition of Done:**
* [ ] The `mailhog` service definition is successfully added to the `infra/docker-compose.yml` file.
* [ ] `mailhog` service is configured to expose ports `1025` (SMTP) and `8025` (HTTP Web UI).
* [ ] All Docker Compose services, including MailHog, successfully start without errors.
* [ ] The MailHog web UI is accessible at `http://localhost:8025` from the host machine's browser.
* [ ] The `docs/local-development.md` is updated to include instructions for accessing the MailHog UI and clear guidance on configuring applications to send emails to MailHog.

**5. Dependencies / Pre-requisites:**
* Completion of **P1-T1: `infra: Setup Local Development Environment with Docker Compose`** (ensures `infra/docker-compose.yml` exists and Docker Compose is operational).
* Existing SaaScript monorepo clone.
* Docker or Podman installed.
