# chore: Setup VSCode Configuration (settings, tasks, launch, extensions)

**1. Rationale:**
Establishing a consistent and efficient development environment for all team members is paramount for the SaaScript monorepo. Configuring Visual Studio Code with standardized settings, tasks, launch configurations, and recommended extensions ensures that every developer (human or AI) operates with the same tooling setup. This minimizes "it works on my machine" issues, streamlines common development workflows (e.g., running tests, building, debugging), enhances code quality through consistent formatting and linting, and improves onboarding velocity, directly contributing to the team's overall productivity and alignment. **Crucially, this setup includes recommendations for core AI-assisted development tools like the Gemini VS Code Extension and GitHub Copilot, central to our workflow.**

**2. Goal:**
To create and populate the `.vscode/` directory at the monorepo root with `settings.json`, `tasks.json`, `launch.json`, and `extensions.json` files. These configurations will optimize VS Code for TypeScript/Node.js/React development within a monorepo structure, integrate with Yarn Workspaces scripts, and facilitate debugging of microservices and frontend applications.

**3. Detailed Steps:**
* Step 1: **Navigate to the SaaScript Monorepo Root.**
    Ensure your current working directory is the root of the `saascript/` monorepo clone.
* Step 2: **Create `.vscode/` Directory.**
    Create the `.vscode/` directory at the monorepo root if it does not already exist. This directory will house all workspace-specific VS Code configurations.
* Step 3: **Create and Configure `settings.json`.**
    Create `settings.json` inside the `.vscode/` directory. This file will contain workspace-specific editor settings, particularly for consistent formatting (Prettier) and linting (ESLint) across TypeScript, JavaScript, and JSON files, ensuring adherence to `code-style-guidelines.md`. It will also configure file and search exclusions appropriately, keeping `node_modules` and build/dist folders visible in the Explorer for debugging purposes.
* Step 4: **Create and Configure `tasks.json`.**
    Create `tasks.json` inside the `.vscode/` directory. This file will define common development tasks that can be run directly from VS Code's "Run Task" menu, leveraging the `yarn` scripts defined in P1-T2. Include tasks for installing dependencies, building, testing, linting, formatting, and starting/stopping the local infrastructure.
* Step 5: **Create and Configure `launch.json`.**
    Create `launch.json` inside the `.vscode/` directory. This file will define debugging configurations for Node.js microservices and potentially React/Next.js frontend applications. At a minimum, provide a basic configuration for attaching to a Node.js process.
* Step 6: **Create and Configure `extensions.json`.**
    Create `extensions.json` inside the `.vscode/` directory. This file recommends essential VS Code extensions to all developers opening the workspace, ensuring consistency in recommended tools and features. **This list must include specific recommendations for the Gemini VS Code Extension and GitHub Copilot, along with other core development tools.**

**4. Acceptance Criteria / Definition of Done:**
* [ ] The `.vscode/` directory is created at the monorepo root.
* [ ] The `settings.json`, `tasks.json`, `launch.json`, and `extensions.json` files are created within `.vscode/`.
* [ ] `settings.json` is configured for consistent formatting (`formatOnSave`, `defaultFormatter`) and ESLint integration, referencing monorepo root configs, while keeping `node_modules` and build/dist folders visible in the Explorer.
* [ ] `tasks.json` contains tasks for `install:all`, `build:all`, `test:all`, `lint:all`, `lint:fix:all`, `format:all`, `start:dev:infra`, and `stop:dev:infra`, leveraging `yarn` scripts.
* [ ] `launch.json` includes at least one functional debug configuration for attaching to a Node.js process (e.g., a NestJS service).
* [ ] `extensions.json` recommends essential VS Code extensions, **including the Gemini VS Code Extension (placeholder ID provided) and GitHub Copilot**, as well as other relevant tools (e.g., Prettier, ESLint, Docker, Tailwind CSS, YAML).
* [ ] When the monorepo is opened in VS Code, recommended extensions are suggested.
* [ ] Running tasks (e.g., "Build All Monorepo Packages") via VS Code's "Run Task" command successfully executes the corresponding `yarn` script.
* [ ] Debugging (e.g., "Attach to NestJS Service") successfully connects to a running Node.js process.

**5. Dependencies / Pre-requisites:**
* Existing SaaScript monorepo clone.
* Visual Studio Code installed.
* Completion of **P1-T1: `infra: Setup Local Development Environment with Docker Compose`** (for `start:dev:infra`/`stop:dev:infra` tasks and debugging Dockerized services).
* Completion of **P1-T2: `chore: Implement Monorepo Tooling (Yarn Workspaces)`** (for all `yarn` scripts used in tasks).

**7. Guidance for Software Engineer AI (GitHub Copilot):**
* **File & Directory Creation:** Create the `.vscode/` directory at the monorepo root. Create empty `settings.json`, `tasks.json`, `launch.json`, and `extensions.json` files within `.vscode/`.
* **`settings.json` Content:** Populate `settings.json` with configurations for:
    * Editor settings: `tabSize`, `insertSpaces`, `detectIndentation`, `formatOnSave`, `defaultFormatter`, `files.eol`.
    * File and Search Exclusions: `files.exclude` (excluding common VCS/temp files but *including* `node_modules` and `dist`/`build` for search, but *not* for Explorer view), `search.exclude`.
    * TypeScript settings: `typescript.tsdk`, `typescript.enablePromptUseWorkspaceTsdk`, `typescript.tsserver.maxTsServerMemory`.
    * ESLint settings: `eslint.enable`, `eslint.run`, `eslint.options.overrideConfigFile`, `editor.codeActionsOnSave`.
    * Prettier settings: `prettier.configPath`, `prettier.documentSelectors`.
    * Docker Compose integration: `docker.dockerCompose.files` pointing to `infra/docker-compose.yml`.
* **`tasks.json` Content:** Populate `tasks.json` with shell tasks (`type: "shell"`) for each of the root-level `yarn` scripts defined in P1-T2: `install:all`, `build:all`, `test:all`, `lint:all`, `lint:fix:all`, `format:all`, `start:dev:infra`, `stop:dev:infra`.
* **`launch.json` Content:** Populate `launch.json` with at least one "Attach to Node.js Service" debug configuration. Consider adding a "Launch NestJS Service (Example)" if a typical launch path is known (e.g., `modules/gateway/src/main.ts`).
