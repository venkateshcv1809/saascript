# chore: Implement Monorepo Tooling (Yarn Workspaces)

**1. Rationale:**
Establishing robust monorepo tooling is essential for efficiently managing multiple interdependent packages and services within the SaaScript project. **Yarn Workspaces** has been chosen as the core monorepo management solution due to its native capabilities for dependency management, cross-package linking, and efficient script execution, offering sufficient functionality with reduced overhead. Implementing core root-level scripts will standardize common development operations (like building, testing, linting) for all developers and AI team members, minimizing configuration overhead and ensuring consistent workflows as outlined in `development-workflow.md`. This task explicitly sets up the `package.json` for managing current and future modules based on the project's defined and evolving structure.

**2. Goal:**
To fully configure Yarn Workspaces within the SaaScript monorepo's root `package.json` and define a comprehensive set of root-level scripts that leverage these workspaces for common operations such as installing dependencies, building all packages, running tests across the monorepo, and executing linting/formatting checks. This will prepare the monorepo for the creation of new services and applications in subsequent tasks, ensuring a unified development experience aligned with the documented folder structure and chosen tooling.

**3. Detailed Steps:**
* Step 1: **Navigate to the SaaScript Monorepo Root.**
    Ensure your current working directory is the root of the `saascript/` monorepo clone.
* Step 2: **Configure Yarn Workspaces and Root Development Dependencies in `package.json`.**
    Open the `package.json` file at the monorepo root (`saascript/package.json`). Ensure the `workspaces` field is present and correctly configured to include paths for all existing and planned top-level application/module directories **as defined in `saascript.md` (Section 2.13: SaaScript Monorepo Folder Structure)**. These paths will allow Yarn to manage dependencies and link packages efficiently.
    It is also essential that this `package.json` explicitly lists the foundational root-level development dependencies required for monorepo-wide operations such as **TypeScript** for compilation, **Jest** for testing, **ESLint** for linting, **Prettier** for formatting, and **Husky** for Git hooks.
    **Add or update the `workspaces` field and `devDependencies` to this exact configuration:**
    ```json
    {
      "name": "saascript",
      "version": "1.0.0",
      "private": true,
      "workspaces": [
        "modules/*",      
        "frontend/*",     
        "e2e/*",          
        "scripts/*"       
      ],
      "scripts": {
        // Scripts to be added in next step
      },
      "devDependencies": {
        "typescript": "^5.0.0",
        "jest": "^29.0.0",
        "eslint": "^8.0.0",
        "prettier": "^3.0.0",
        "husky": "^9.0.0"
      }
    }
    ```
    * **Rationale for paths (aligned with `saascript.md` Section 2.13):**
        * `modules/*`: To cover all microservices and shared libraries within the `modules/` directory (e.g., `modules/gateway`, `modules/auth_service`, `modules/libs/*`).
        * `frontend/*`: To cover all frontend applications within the `frontend/` directory (e.g., `frontend/web`, `frontend/admin`).
        * `e2e/*`: For the End-to-End (E2E) test suites.
        * `scripts/*`: For utility scripts.
* Step 3: **Define Root-Level Monorepo Scripts in `package.json`.**
    Add or update the `scripts` section in the root `saascript/package.json` file to include commands for common monorepo operations. These scripts should utilize `yarn` commands (e.g., `yarn workspaces run`, `yarn install`, `yarn build`, `yarn test`, `yarn lint`, `yarn format`). Include scripts to manage the local Docker Compose infrastructure.
    **Required Scripts:**
    * `install:all`: Installs all dependencies across all workspaces.
    * `build:all`: Builds all compilable packages/services (modules and frontends).
    * `test:all`: Runs all tests across the monorepo.
    * `lint:all`: Runs linting checks across all relevant packages.
    * `lint:fix:all`: Runs linting checks and attempts to fix issues across all relevant packages.
    * `format:all`: Formats code using Prettier across all relevant packages.
    * `start:dev:infra`: Starts the Docker Compose infrastructure.
    * `stop:dev:infra`: Stops the Docker Compose infrastructure.
    * `clean:all`: Cleans build artifacts and `node_modules` across workspaces.
* Step 4: **Validate Monorepo Script Functionality.**
    After adding the scripts, perform basic tests to ensure they function as expected.
    * Run `yarn install:all` to confirm all packages' dependencies are correctly installed and linked.
    * Run `yarn start:dev:infra` and `yarn stop:dev:infra` to verify Docker Compose control.
    * Run `yarn lint:all`, `yarn lint:fix:all`, `yarn format:all` to ensure they execute without syntax errors (even if no files are processed yet).
