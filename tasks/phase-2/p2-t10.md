# feat(saascript-auth-service): Implement Token Management (JWT Validation)

**1. Rationale:**
Effective token management is paramount for securing and scaling API-driven microservices. While P2-T9 introduced JWT generation, this task focuses on the critical next step: robust **JWT validation and lifecycle management**. Implementing a standardized approach for validating incoming JWTs within the `saascript-auth-service` (and later, enabling other services to do so) ensures that all requests from authenticated users are legitimate. This task also lays the conceptual groundwork for advanced token features like refresh and revocation, crucial for enhancing user experience (long-lived sessions without re-login) and security (immediately invalidating compromised tokens). This is a core security best practice for stateless authentication in a microservices environment.

**2. Goal:**
To implement a robust JWT validation mechanism within the `saascript-auth-service` using `@nestjs/passport` and `passport-jwt`. This includes:
* Creating a JWT strategy to extract and validate tokens against the configured secret.
* Implementing a JWT guard to protect API endpoints, ensuring only authenticated requests can access them.
* Enhancing the login response to potentially include both access and refresh tokens.
* Establishing the architectural approach for token refresh and revocation, even if full implementation details are deferred to a later phase.

**3. Detailed Steps:**
* Step 1: **Navigate to the Auth Microservice Directory.**
    Ensure your current working directory is `modules/auth_service/`.
* Step 2: **Install Passport and JWT-Passport Dependencies.**
    Install `@nestjs/passport`, `passport`, `passport-jwt`, and their corresponding `@types` as dependencies within `modules/auth_service/`.
* Step 3: **Configure JWT Secret Management.**
    Ensure the JWT secret (and potentially refresh token secret) is securely managed, ideally retrieved from environment variables using `@nestjs/config` within the `AuthModule`.
* Step 4: **Implement a Custom JWT Strategy.**
    Create a new file (e.g., `modules/auth_service/src/auth/jwt.strategy.ts`) that defines a custom Passport JWT strategy. This strategy will be responsible for extracting the JWT from the request header, verifying its signature using the secret, and validating the token's payload (e.g., `userId`, `email`).
* Step 5: **Implement a JWT Guard.**
    Create a new file (e.g., `modules/auth_service/src/auth/jwt.guard.ts`) that extends `AuthGuard('jwt')`. This guard will protect routes by ensuring that requests carry a valid JWT.
* Step 6: **Update Auth Module for Passport Integration.**
    Modify `modules/auth_service/src/auth/auth.module.ts` to register `PassportModule` and provide the custom `JwtStrategy`. Ensure `JwtModule` is correctly configured.
* Step 7: **Protect a Test Endpoint with the JWT Guard.**
    In `modules/auth_service/src/auth/auth.controller.ts`, protect an existing (or new) test endpoint (e.g., a simple `/auth/profile` endpoint that returns authenticated user info) by applying the `JwtGuard` via the `@UseGuards()` decorator.
* Step 8: **Enhance Login Endpoint Response (Access & Refresh Tokens).**
    Modify the `POST /auth/login` endpoint's response (`AuthResponseDto`) to include both a short-lived **access token** (JWT) and a longer-lived **refresh token** (typically stored securely client-side and used to obtain new access tokens).
* Step 9: **Outline Token Refresh and Revocation Strategy.**
    Document the high-level strategy for:
    * **Token Refresh:** How a refresh token will be used to obtain a new access token (e.g., a new endpoint `POST /auth/refresh-token`). This would involve validating the refresh token and issuing a new pair.
    * **Token Revocation:** How access and/or refresh tokens can be invalidated (e.g., for logout, password change, compromise). This often involves a blacklist/whitelist mechanism, likely utilizing Redis (a future dedicated task might be needed for the shared Redis cache module).
* Step 10: **Install Monorepo Dependencies.**
    Execute the monorepo-wide dependency installation command to ensure all new packages are correctly installed.
* Step 11: **Build and Run the Auth Microservice.**
    Build the `auth_service` and then start it in development mode.
* Step 12: **Test JWT Validation.**
    Use an API client to:
    * Log in to obtain an access token.
    * Attempt to access the protected `/auth/profile` endpoint with:
        * The valid access token.
        * An invalid/expired access token.
        * No token.
    * Verify `200 OK` for valid tokens and `401 Unauthorized` for invalid/missing tokens, adhering to the standardized error handling (P2-T6).
* Step 13: **Document Token Management.**
    Update `docs/api-contracts.md` to detail the new protected endpoints and the structure of JWTs (payload, expiration). Update `docs/security.md` to thoroughly explain the JWT validation flow, the role of access and refresh tokens, and the conceptual approach to token refresh and revocation, referencing the use of Passport.js and JWT strategy.
