# chore(saascript-core-services): Define & Implement Basic Input Validation Standard

**1. Rationale:**
Input validation and sanitization are critical security and reliability best practices for any API-driven application. Implementing a consistent and robust standard for this across all microservices from early development prevents common vulnerabilities (e.g., SQL injection, XSS, unexpected data formats), improves data integrity, and enhances the predictability of API behavior. This task focuses on establishing a common approach, leveraging libraries like `class-validator` and `class-transformer` within NestJS, and integrating it into our services to ensure all incoming data adheres to defined schemas and constraints, aligning with our commitment to secure and high-quality code.

**2. Goal:**
To define a standardized approach for input validation using `class-validator` and `class-transformer` in NestJS. This includes creating a shared DTO (Data Transfer Object) structure for validation, implementing a global `ValidationPipe` in core services (like the API Gateway and Auth Service), and demonstrating its effectiveness by defining a basic validated DTO for a conceptual input (e.g., a user registration request) and testing its enforcement.

**3. Detailed Steps:**
* Step 1: **Navigate to the Monorepo Root.**
    Ensure your current working directory is the root of the `saascript/` monorepo clone.
* Step 2: **Install Validation Dependencies at Monorepo Root.**
    Install `class-validator` and `class-transformer` as regular dependencies at the monorepo root (`saascript/package.json`). These are often used across multiple NestJS projects, so installing them at the root level via Yarn Workspaces makes them available to all.
* Step 3: **Create Shared DTOs/Validation Library (Optional but Recommended).**
    Consider creating a new shared library for common DTOs and validation rules (e.g., `modules/libs/common/dtos/` or similar) if complex, reusable DTOs are anticipated. For this basic task, DTOs can initially reside within the service they are validating.
* Step 4: **Implement Global Validation Pipe in API Gateway.**
    Modify the `modules/gateway/src/main.ts` file to register a global `ValidationPipe`. This pipe will automatically validate incoming request bodies against the DTOs used in controller methods.
* Step 5: **Define a Basic Validated DTO in Auth Service.**
    In the `modules/auth_service/`, create a new DTO (e.g., `src/auth/dtos/create-user.dto.ts`). This DTO should define properties with `class-validator` decorators (e.g., `@IsString()`, `@IsEmail()`, `@MinLength()`, `@IsNotEmpty()`).
* Step 6: **Create a Test Endpoint in Auth Service (or API Gateway).**
    In `modules/auth_service/src/app.controller.ts` (or a new `auth.controller.ts`), create a new POST endpoint that accepts the `CreateUserDto` as its request body parameter. This endpoint will be used to test the validation.
* Step 7: **Install Monorepo Dependencies (Again).**
    After installing new dependencies (`class-validator`, `class-transformer`), execute `yarn install:all` at the monorepo root.
* Step 8: **Test Input Validation Enforcement.**
    Run the API Gateway and Auth Service. Send a request to the newly created test endpoint with invalid data (e.g., missing required fields, invalid email format). Verify that the API returns a `400 Bad Request` response with detailed validation errors, conforming to the standardized error handling established in P2-T6.
* Step 9: **Document Input Validation Standard.**
    Update `docs/architecture.md` (under a new "API Design & Input Validation" section) and `docs/api-contracts.md` (if existing) or `docs/security.md` to document the input validation standard. Explain the use of `class-validator` and `class-transformer`, the global `ValidationPipe`, and provide examples of how DTOs should be defined and how validation errors will be formatted.
