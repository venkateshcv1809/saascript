# feat(saascript-auth-service): Integrate PostgreSQL for Auth Microservice

**1. Rationale:**
The Authentication Microservice (`auth_service`) requires a persistent data store for managing user accounts, roles, and other authentication-related information. Integrating it with PostgreSQL, our chosen relational database, is a critical step. By leveraging the shared `saascript-libs-database-postgres` module (P2-T1), we ensure consistent, robust, and best-practice database connectivity. This task focuses on defining the initial database entities specific to authentication within `auth_service` and setting up the service to interact with these entities, laying the groundwork for user management functionalities in later phases. This directly supports the project's goal of implementing best practices in data persistence.

**2. Goal:**
To successfully integrate the `saascript-auth-service` with the shared `saascript-libs-database-postgres` module. This includes configuring the Auth Service's NestJS application to use TypeORM via the shared module, defining the initial `User` entity, and ensuring the service can connect to the PostgreSQL database and perform basic ORM operations (e.g., entity synchronization for development, though migrations will be used in production).

**3. Detailed Steps:**
* Step 1: **Navigate to the Auth Microservice Directory.**
    Ensure your current working directory is `modules/auth_service/`.
* Step 2: **Install Auth Service-Specific Database Dependencies.**
    Install any additional TypeORM-related dependencies that are specifically required by `auth_service` and not fully encapsulated by the shared database module (e.g., `@nestjs/typeorm` for injecting repositories).
* Step 3: **Integrate Shared PostgreSQL Module into Auth Service.**
    Modify the main NestJS application module (`app.module.ts` or a dedicated `auth.module.ts`) within `modules/auth_service/` to import the `PostgresModule` from `saascript-libs-database-postgres`. Configure it to register the entities specific to the Auth Service using `TypeOrmModule.forFeature()`.
* Step 4: **Define Auth-Specific Database Entities.**
    Create the initial database entity/entities for the Authentication Microservice (e.g., `UserEntity`). This entity should be defined with TypeORM decorators for schema mapping, including primary keys, columns (e.g., `email`, `passwordHash`), and timestamps (`createdAt`, `updatedAt`).
* Step 5: **Configure `tsconfig.json` for Entity Recognition.**
    Ensure the `tsconfig.json` in `modules/auth_service/` is configured to correctly include the newly defined entity files for TypeScript compilation.
* Step 6: **Update Auth Service `package.json` (Optional).**
    If specific TypeORM CLI commands (e.g., for local schema updates or migration generation during development) are to be run directly from this service, add corresponding scripts to its `package.json`.
* Step 7: **Install Monorepo Dependencies.**
    Execute the monorepo-wide dependency installation command to ensure all new dependencies and module linkages (including the shared database module) are correctly resolved.
* Step 8: **Build and Run the Auth Microservice.**
    Build the `auth_service` and then start it in development mode.
* Step 9: **Verify Database Connection and Entity Setup.**
    During the `auth_service` startup, observe its console logs to confirm a successful connection to the PostgreSQL database. If temporary `synchronize: true` is enabled in development, verify that the necessary tables (e.g., `users` table) are created in the local PostgreSQL database.
* Step 10: **Document PostgreSQL Integration for Auth Service.**
    Update `docs/microservices.md` (specifically the entry for `auth_service`) to detail its PostgreSQL integration, the entities it manages (e.g., `UserEntity`), and how it utilizes the shared `saascript-libs-database-postgres` module.
