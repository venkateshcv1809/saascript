# chore(saascript-core-services): Implement Standardized API Error Handling

**1. Rationale:**
Consistent and predictable API error handling is a fundamental best practice for any robust microservices architecture. Without it, client applications struggle to interpret failures, and debugging becomes cumbersome. This task establishes and implements a standardized, application-wide error handling mechanism and response format for all backend microservices (e.g., API Gateway, Auth Service, User Profile Service, etc.). This significantly improves the API contract predictability, enhances the developer experience for consumers of our APIs, simplifies debugging, and contributes to the overall reliability and maintainability of the SaaScript platform. This centralized approach aligns with our best practices for modularity and reusability across services.

**2. Goal:**
To create a shared NestJS module (`ErrorHandlingModule`) within a new common library (e.g., `modules/libs/common/error-handling/`) that provides standardized exception filters, interceptors, and DTOs for consistent API error responses. This module will then be integrated into the API Gateway and other core microservices to ensure all errors are caught, transformed into a predictable format (e.g., JSON with `statusCode`, `message`, `error` fields), and returned to clients uniformly.

**3. Detailed Steps:**
* Step 1: **Navigate to the `modules/libs/common/` Directory.**
    Ensure your current working directory is `modules/libs/common/` at the monorepo root. Create this directory if it doesn't exist.
* Step 2: **Create the `error-handling/` Module Directory.**
    Create the `error-handling/` directory inside `modules/libs/common/`. This will be the root for the shared error handling module.
* Step 3: **Initialize Node.js Project and Install Dependencies.**
    Initialize a new Node.js project within `modules/libs/common/error-handling/`. Install necessary NestJS packages (`@nestjs/common`, `@nestjs/core`) and TypeScript dev dependencies.
* Step 4: **Create `tsconfig.json` for the Error Handling Module.**
    Create a `tsconfig.json` file inside `modules/libs/common/error-handling/` to configure TypeScript compilation for this shared library.
* Step 5: **Create `src/` Directory and Error Handling Module Files.**
    Create the `src/` directory within `modules/libs/common/error-handling/` and populate it with:
    * `error-handling.module.ts`: The main NestJS module.
    * `all-exceptions.filter.ts`: A global exception filter (implements `ExceptionFilter`) to catch all unhandled exceptions and transform them into a standard API error response format.
    * `http-exception.filter.ts` (Optional): A more specific filter for NestJS `HttpException` if different handling is needed.
    * `standard-error.interceptor.ts` (Optional): An interceptor to ensure all responses conform to a standard structure, even successful ones, or to add common error details.
    * `dtos/` directory with `error-response.dto.ts`: A DTO defining the standardized JSON structure for API error responses.
* Step 6: **Update Error Handling Module `package.json` Scripts.**
    Modify the `package.json` within `modules/libs/common/error-handling/` to include necessary scripts, particularly `build`.
* Step 7: **Update Monorepo Root `package.json` Workspaces.**
    Add `modules/libs/common/error-handling` to the `workspaces` array in the monorepo's root `package.json` (`saascript/package.json`) to ensure Yarn recognizes this new shared module.
* Step 8: **Install Monorepo Dependencies.**
    Execute `yarn install:all` at the monorepo root to ensure all new dependencies for the error handling module are installed and cross-linked correctly within the monorepo.
* Step 9: **Build the Error Handling Module.**
    Build the newly created `saascript-libs-common-error-handling` module to ensure it compiles correctly.
* Step 10: **Integrate Error Handling Module into API Gateway.**
    Modify the `modules/gateway/src/main.ts` file to register the `AllExceptionsFilter` globally using `app.useGlobalFilters()`. Ensure that `ValidationPipe` or similar pipes are also configured for request validation, which can throw `HttpException`s.
* Step 11: **Test Standardized Error Response.**
    Run the API Gateway service. Create a test endpoint or trigger an existing one to cause an error (e.g., throwing a `BadRequestException` or a generic `Error`). Verify that the API response conforms to the standardized error DTO (e.g., `statusCode`, `message`, `error` fields).
* Step 12: **Document Standardized Error Handling.**
    Update `docs/architecture.md` (specifically under "API Gateway" or a new "API Design & Error Handling" section) and `docs/api-contracts.md` (if existing, or create it) to detail the standardized error response format and the implementation of the shared error handling module. Provide examples of expected error responses.
