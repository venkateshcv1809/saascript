# feat(saascript-modules-projects): Integrate PostgreSQL for Project Service Data

**1. Rationale:**
The Project Management microservice requires a persistent data store for managing project-related entities such as projects themselves, tasks, and potentially users assigned to projects. Integrating it with PostgreSQL, our chosen relational database, is fundamental for storing this core business data. By leveraging the shared `saascript-libs-database-postgres` module (P2-T1), we ensure consistent, robust, and best-practice database connectivity. This task focuses on defining the initial database entities specific to project management within `saascript-modules-projects` and setting up the service to interact with these entities, laying the groundwork for CRUD operations on projects in the next task.

**2. Goal:**
To successfully integrate the `saascript-modules-projects` microservice with the shared `saascript-libs-database-postgres` module. This includes configuring the Project Service's NestJS application to use TypeORM via the shared module, defining the initial `Project` entity (and potentially `Task` entity), and ensuring the service can connect to the PostgreSQL database and manage its entities.

**3. Detailed Steps:**
* Step 1: **Navigate to the Project Microservice Directory.**
    Ensure your current working directory is `modules/modules/projects/`.
* Step 2: **Install Project Service-Specific Database Dependencies.**
    Install any additional TypeORM-related dependencies within `modules/modules/projects/` if not already covered by the shared module (e.g., `@nestjs/typeorm` for injecting repositories).
* Step 3: **Integrate Shared PostgreSQL Module into Project Service.**
    Modify the main NestJS application module (`app.module.ts` or a dedicated `projects.module.ts`) within `modules/modules/projects/` to import the `PostgresModule` from `saascript-libs-database-postgres`. Configure the `TypeOrmModule.forFeature()` to register the specific entities for the `saascript-modules-projects` (e.g., `ProjectEntity`).
* Step 4: **Define Project-Specific Database Entities.**
    Create a new directory for entities within `modules/modules/projects/src/entities/` (e.g., `src/entities/project.entity.ts`). Define the basic `Project` entity with necessary TypeORM decorators (`@Entity`, `@PrimaryGeneratedColumn`, `@Column`) for fields like `id`, `name`, `description`, `ownerId` (linking to a user), `createdAt`, `updatedAt`.
* Step 5: **Configure `tsconfig.json` for Entity Recognition.**
    Ensure the `tsconfig.json` in `modules/modules/projects/` is configured to correctly include the new entity files for TypeScript compilation.
* Step 6: **Update Project Service `package.json` for ORM (Optional).**
    If TypeORM CLI commands are needed for this service (e.g., `typeorm migration:generate`), add them to `modules/modules/projects/package.json`.
* Step 7: **Install Monorepo Dependencies.**
    Execute the monorepo-wide dependency installation command to ensure all new dependencies and module linkages are correctly handled.
* Step 8: **Build and Run the Project Microservice.**
    Build the `saascript-modules-projects` and then start it in development mode.
* Step 9: **Verify Database Connection and Entity Setup.**
    Observe the console logs of the `saascript-modules-projects` during startup to confirm a successful connection to the PostgreSQL database. If `synchronize: true` is enabled in development (temporarily), check the PostgreSQL database to ensure the `projects` table is created.
* Step 10: **Document PostgreSQL Integration for Project Service.**
    Update `docs/microservices.md` (specifically the entry for `saascript-modules-projects`) to detail its PostgreSQL integration, the entities it manages (e.g., `ProjectEntity`), and how it utilizes the shared `saascript-libs-database-postgres` module.
