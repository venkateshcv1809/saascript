# feat(saascript-gateway): Implement Auth Token Validation & Routing

**1. Rationale:**
As the single entry point to the backend, the API Gateway plays a crucial role in securing our microservices by validating authentication tokens and routing requests appropriately. This task focuses on enhancing the `saascript-gateway` to perform JWT validation (without duplicating `auth_service`'s logic) and then securely forwarding authenticated requests to downstream services, particularly the `auth_service` itself for profile or other authenticated operations. This centralizes authentication enforcement, reduces boilerplate in individual microservices, and ensures a consistent security posture across the SaaScript platform, aligning with our best practices for API Gateway design and security.

**2. Goal:**
To implement JWT validation within the `saascript-gateway` and configure intelligent routing for authenticated requests. This involves:
* Setting up `@nestjs/passport` and a JWT strategy in the Gateway to validate tokens using the same secret as the `auth_service`.
* Implementing a global authentication guard in the Gateway to protect routes.
* Proxying authenticated requests to the `auth_service` and eventually other microservices.
* Ensuring the Gateway handles authentication failures gracefully, conforming to the standardized error handling (P2-T6).
* Optionally, enriching the request with user information extracted from the JWT payload before forwarding.

**3. Detailed Steps:**
* Step 1: **Navigate to the API Gateway Service Directory.**
    Ensure your current working directory is `modules/gateway/`.
* Step 2: **Install Passport and JWT-Passport Dependencies.**
    Install `@nestjs/passport`, `passport`, `passport-jwt`, and their corresponding `@types` as dependencies within `modules/gateway/`.
* Step 3: **Configure JWT Secret Management.**
    Ensure the JWT secret used by the Gateway for token validation is consistent with the one used by the `auth_service` (retrieved from environment variables using `@nestjs/config`).
* Step 4: **Implement a Custom JWT Strategy for the Gateway.**
    Create a new file (e.g., `modules/gateway/src/auth/jwt.strategy.ts`) that defines a custom Passport JWT strategy. This strategy will extract and verify the JWT signature using the shared secret. Its `validate` method will simply return the decoded payload, as full user validation is `auth_service`'s responsibility.
* Step 5: **Implement a JWT Guard for the Gateway.**
    Create a new file (e.g., `modules/gateway/src/auth/jwt.guard.ts`) that extends `AuthGuard('jwt')`. This guard will be used to protect specific API Gateway routes.
* Step 6: **Update Gateway Auth Module for Passport Integration.**
    Modify `modules/gateway/src/app.module.ts` (or a dedicated Gateway `auth` module if created) to register `PassportModule` and provide the custom `JwtStrategy`. Ensure `JwtModule` is correctly configured with the shared secret.
* Step 7: **Implement Proxying to Auth Microservice.**
    Using NestJS's microservice capabilities or HTTP proxying (e.g., `@nestjs/platform-express` with a custom proxy setup, or potentially a dedicated `http-proxy-middleware`), configure the Gateway to:
    * Route specific authenticated paths (e.g., `/auth/profile`) to the `auth_service`'s internal URL.
    * Forward the original `Authorization` header containing the JWT.
    * Potentially, attach extracted user information from the JWT payload to the request object for downstream microservices to consume.
* Step 8: **Protect Gateway Routes.**
    Apply the newly created `JwtGuard` to relevant API Gateway routes (e.g., `/auth/profile`) using the `@UseGuards()` decorator. For simplicity, initially apply it to the `AppController`'s `getHello` method if no other protected routes exist yet.
* Step 9: **Install Monorepo Dependencies.**
    Execute the monorepo-wide dependency installation command.
* Step 10: **Build and Run the API Gateway and Auth Microservice.**
    Start both the `saascript-gateway` and `saascript-auth-service` in development mode.
* Step 11: **Test Auth Token Validation and Routing.**
    Use an API client to:
    * Log in via the Gateway (`POST /auth/login`) to obtain a valid JWT.
    * Use the obtained JWT to access a protected endpoint on the Gateway that proxies to `auth_service` (e.g., `GET /auth/profile`).
    * Test with invalid/expired tokens and no token to verify `401 Unauthorized` responses from the Gateway, conforming to P2-T6.
* Step 12: **Document Auth Token Validation and Routing.**
    Update `docs/architecture.md` (specifically the "API Gateway" section) and `docs/security.md` to detail how the API Gateway handles JWT validation, token forwarding, and routing to downstream microservices, emphasizing that it acts as the central authentication enforcement point.

**7. Guidance for Software Engineer AI (GitHub Copilot):**
* **Dependency Installation:** In `modules/gateway/`, install `yarn add @nestjs/passport passport passport-jwt @types/passport-jwt`.
* **JWT Strategy for Gateway:** Create `modules/gateway/src/auth/jwt.strategy.ts`. This strategy will primarily extract the token and verify its signature using the shared secret. Its `validate` method should typically return the decoded payload directly (e.g., `{ userId, email }`), as deep validation is for `auth_service`.
* **JWT Guard for Gateway:** Create `modules/gateway/src/auth/jwt.guard.ts`. Define a `JwtAuthGuard` class extending `AuthGuard('jwt')`.
* **Gateway Module Configuration:** In `modules/gateway/src/app.module.ts`:
    * Import `PassportModule.register({ defaultStrategy: 'jwt' })`.
    * Import `JwtModule.registerAsync()` if using dynamic secret loading (recommended) or `JwtModule.register()` with the secret from `@nestjs/config`.
    * Add `JwtStrategy` as a provider.
* **Proxy Configuration:**
    * Use NestJS's built-in HTTP module (`@nestjs/axios`) or a dedicated proxy setup.
    * In a Gateway controller (e.g., `AppController` or a new `AuthProxyController`), implement a route (e.g., `GET /auth/profile`).
    * Inside this route, use `HttpService` to make a request to the *internal* `auth_service` URL (e.g., `http://auth_service:3001/profile`), forwarding the `Authorization` header from the original request.
    * Example proxy logic (conceptual, exact implementation might vary with `@nestjs/axios` or custom setup):
        ```typescript
        // In Gateway's AppController or a new AuthProxyController
        import { Controller, Get, Req, UseGuards } from '@nestjs/common';
        import { JwtAuthGuard } from './auth/jwt.guard'; // Gateway's JWT Guard
        import { HttpService } from '@nestjs/axios';
        import { Request } from 'express'; // or any request type

        @Controller('auth')
        export class AuthProxyController {
          constructor(private readonly httpService: HttpService) {}

          @UseGuards(JwtAuthGuard)
          @Get('profile')
          async getProfile(@Req() req: Request) {
            // Get the JWT from the original request
            const authHeader = req.headers.authorization;
            if (!authHeader) {
                // This case should ideally be handled by the guard already
                throw new UnauthorizedException('Authorization header missing');
            }

            // Forward the request to the internal Auth Service URL
            // 'auth_service' is the Docker Compose service name for the Auth microservice
            const authServiceUrl = process.env.AUTH_SERVICE_URL || 'http://auth_service:3001';
            const response = await this.httpService.get(`${authServiceUrl}/profile`, {
              headers: { Authorization: authHeader },
            }).toPromise(); // .toPromise() needed for Axios version used by HttpService

            return response.data;
          }
        }
        ```
    * Ensure `AuthProxyController` is included in `AppModule` controllers. Add `HttpModule` to `AppModule` imports.
* **Protected Routes:** Apply `@UseGuards(JwtAuthGuard)` to the relevant Gateway routes.
