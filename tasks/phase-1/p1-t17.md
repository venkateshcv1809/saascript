# chore: Setup End-to-End (E2E) Testing Framework

**1. Rationale:**
The End-to-End (E2E) testing framework is the apex of our testing pyramid, crucial for validating the full system functionality of the integrated SaaScript application from a user's perspective. While unit and backend integration tests verify individual components and their API interactions, E2E tests simulate real user flows through the UI, interacting with all integrated microservices (frontend, API Gateway, Auth Service, etc.) and underlying infrastructure. This comprehensive validation ensures critical user journeys work as expected in an environment closely mirroring production, catches issues that lower-level tests might miss, and aligns directly with the project's commitment to delivering a high-quality, reliable user experience and best practices in software quality assurance.

**2. Goal:**
To successfully install and configure **Playwright** as the robust E2E testing framework within the `e2e/` directory at the monorepo root. This includes initial setup files, a basic example E2E test that interacts with the `saascript-frontend-web` application (e.g., verifying the landing page content), and updating monorepo scripts for running E2E tests. This task will solidify the top layer of our testing pyramid.

**3. Detailed Steps:**
* Step 1: **Navigate to the Monorepo Root.**
    Ensure your current working directory is the root of the `saascript/` monorepo clone.
* Step 2: **Install Playwright and Dependencies.**
    Install `@playwright/test` and its necessary browser drivers/dependencies as dev dependencies at the monorepo root.
* Step 3: **Initialize Playwright Configuration.**
    Initialize Playwright within the `e2e/` directory (created in P1-T16). This will generate essential configuration files (e.g., `playwright.config.ts`, `tests/example.spec.ts`) and set up the basic test runner structure.
* Step 4: **Create Basic E2E Test Case.**
    Within the `e2e/` directory (following Playwright's generated structure, likely `e2e/tests/`), create a simple E2E test file (e.g., `e2e/tests/landing-page-smoke.spec.ts`). This test should navigate to the `saascript-frontend-web` landing page (`http://localhost:3000`) and assert that key elements or text are present, demonstrating successful end-to-end communication through the UI and backend. This test is explicitly **UI-driven**.
* Step 5: **Update Root `package.json` for E2E Tests.**
    Add or update a dedicated `test:e2e` script in the root `saascript/package.json` to execute the Playwright E2E tests. This script must ensure that all necessary services (frontend, API Gateway, backend microservices, and infrastructure) are running *before* the E2E tests attempt to interact with them.
* Step 6: **Install Monorepo Dependencies (Again).**
    After installing new dev dependencies for Playwright, execute `yarn install:all` at the monorepo root to ensure all dependencies are correctly linked.
* Step 7: **Prepare Test Environment and Run E2E Tests.**
    Ensure all dependent Docker Compose services (frontend, backend services, infrastructure) are running via `yarn start:dev:infra`. Then, execute the new `test:e2e` script from the monorepo root.
* Step 8: **Verify E2E Test Execution and Documentation.**
    Confirm that the E2E tests execute successfully, launch a browser, interact with the running application, and pass. Verify that the `docs/development-workflow.md` is updated to include this E2E testing phase, detailing its purpose, setup, and execution. Ensure the "Testing Pyramid" explanation in `docs/development-workflow.md` and `docs/code-style-guidelines.md` is complete, clearly positioning UI-driven E2E tests at the top.

**7. Guidance for Software Engineer AI (GitHub Copilot):**
* **E2E Framework Installation:** At the monorepo root, execute `yarn add -D @playwright/test` and then `npx playwright install` to install browser binaries.
* **E2E Project Initialization:** Navigate to the `e2e/` directory. Execute `npx playwright test --init`. This will generate `playwright.config.ts`, a `tests/` subdirectory with an example test, and other necessary files.
* **Basic E2E Test Case:** Create a new test file within `e2e/tests/`, for example, `e2e/tests/landing-page-smoke.spec.ts`. Populate it with a basic Playwright test:
    ```typescript
    import { test, expect } from '@playwright/test';

    test('has title and basic content on landing page', async ({ page }) => {
      await page.goto('http://localhost:3000'); // Assuming frontend runs on 3000
      // Expect a title "to contain" a substring.
      await expect(page).toHaveTitle(/SaaScript/);

      // Expect h1 to contain a specific text
      await expect(page.locator('h1')).toContainText('Welcome to SaaScript');

      // Expect "Learn More" link to be visible
      await expect(page.getByRole('link', { name: 'Learn More' })).toBeVisible();
    });
    ```
* **Root `package.json` Update:** Add or modify the `test:e2e` script in the root `saascript/package.json`:
    ```json
    {
      "scripts": {
        "test:e2e": "playwright test --project=chromium" // Or other projects as defined in playwright.config.ts
      }
    }
    ```
    * **Important Note:** Remind the user that `test:e2e` assumes all services (frontend, backend, infrastructure) are *already running*. The Project Owner will need to ensure a workflow for this (e.g., running `yarn start:dev:infra` and then `yarn workspace saascript-frontend-web dev` before `yarn test:e2e`).
* **Dependency Installation (Monorepo):** After adding new dev dependencies, execute `yarn install:all` at the monorepo root.
* **Verification Steps:** Instruct the user to ensure all Docker Compose services (frontend, backend, infra) are running via `yarn start:dev:infra` and that the frontend is running (e.g., `yarn workspace saascript-frontend-web dev`). Then, guide them to run the E2E tests using `yarn test:e2e` from the monorepo root.
