# feat(saascript-auth-service): Implement User Registration & Login Endpoints

**1. Rationale:**
User registration and login are the most fundamental features of any multi-user application, providing secure access and personalization. Developing these core APIs within the `saascript-auth-service` is critical as it serves as the gateway for users to interact with the SaaScript platform. This task encompasses implementing secure password hashing, user persistence in PostgreSQL (leveraging P2-T8), and generating JSON Web Tokens (JWTs) for stateless authentication. This directly contributes to establishing a secure and functional authentication system, aligning with our architectural principles and security best practices.

**2. Goal:**
To implement secure and robust API endpoints within the `saascript-auth-service` for user registration and login. This includes:
* Defining request and response Data Transfer Objects (DTOs) for these operations.
* Implementing secure password hashing for new user registrations.
* Persisting user data (email, hashed password) to the PostgreSQL database.
* Authenticating users against stored credentials.
* Generating and returning JWTs upon successful registration or login.
* Ensuring these endpoints adhere to the standardized input validation (P2-T7) and error handling (P2-T6) mechanisms.

**3. Detailed Steps:**
* Step 1: **Navigate to the Auth Microservice Directory.**
    Ensure your current working directory is `modules/auth_service/`.
* Step 2: **Install Authentication-Related Dependencies.**
    Install necessary packages for password hashing (e.g., `bcryptjs`, `@types/bcryptjs`) and JSON Web Token (JWT) management (e.g., `@nestjs/jwt`, `jsonwebtoken`, `@types/jsonwebtoken`).
* Step 3: **Create Dedicated Auth Module, Service, and Controller.**
    Refactor the basic `app.module.ts` and `app.controller.ts` into a more structured `auth.module.ts`, `auth.service.ts`, and `auth.controller.ts` within `modules/auth_service/src/auth/` for better organization and separation of concerns.
* Step 4: **Define Registration and Login DTOs.**
    Create specific DTOs for user registration requests (e.g., `RegisterUserDto`) and login requests (e.g., `LoginUserDto`) within `modules/auth_service/src/auth/dtos/`. These DTOs must utilize `class-validator` decorators for input validation. Also, define DTOs for successful responses (e.g., `AuthResponseDto` containing JWT and user info).
* Step 5: **Implement User Registration Logic.**
    In `auth.service.ts`, implement the logic for user registration:
    * Hash the user's password securely before saving.
    * Save the new user (email, hashed password) to the PostgreSQL database via the `UserEntity` repository.
    * Handle duplicate email registration attempts gracefully.
* Step 6: **Implement User Login Logic.**
    In `auth.service.ts`, implement the logic for user login:
    * Retrieve the user by email from the database.
    * Compare the provided password with the stored hashed password.
    * Generate a JWT (containing relevant user information like `userId`, `email`) upon successful authentication.
* Step 7: **Expose API Endpoints in Auth Controller.**
    In `auth.controller.ts`, expose POST endpoints for `/auth/register` and `/auth/login` that consume the respective DTOs and delegate logic to the `AuthService`.
* Step 8: **Update Auth Service `main.ts` and `app.module.ts`.**
    Ensure `modules/auth_service/src/main.ts` correctly bootstraps the main application module (`AppModule`), which should now import `AuthModule`.
* Step 9: **Configure JWT Secret and Module.**
    Configure the NestJS `JwtModule` in `auth.module.ts` to use a secret key (retrieved from environment variables via `@nestjs/config`) for signing and verifying JWTs.
* Step 10: **Install Monorepo Dependencies.**
    Execute the monorepo-wide dependency installation command to ensure all new packages are correctly installed.
* Step 11: **Build and Run the Auth Microservice.**
    Build the `auth_service` and then start it in development mode.
* Step 12: **Test Registration and Login Endpoints.**
    Use `curl` or an API client (like Postman) to:
    * Attempt to register a new user (valid and invalid inputs, duplicate email).
    * Attempt to log in with valid and invalid credentials.
    * Verify successful responses include a JWT.
    * Verify error responses adhere to the standardized format (P2-T6).
* Step 13: **Document API Endpoints and Security Considerations.**
    Update `docs/api-contracts.md` (or similar) to document the `POST /auth/register` and `POST /auth/login` endpoints, their request/response DTOs, and expected error codes. Update `docs/security.md` to detail password hashing, JWT structure, and basic security considerations (e.g., token expiration, client-side storage recommendations).
